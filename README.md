# Budget Wallet Details Bot

Telegram-бот для общего семейного учёта расходов. Трата выбирается кнопкой категории или пишется текстом. Бот сохраняет её в PostgreSQL, а статистика открывается в том же сообщении.

## Возможности

- Whitelist по Telegram ID (доступ только указанным пользователям, только в личном чате). Постороннему бот показывает его Telegram ID, чтобы тот передал его владельцу
- Фиксированные категории. Свободное слово не создаёт новую категорию, а сохраняется как пояснение: `комиксы 2800` — это «Развлечения», пояснение «комиксы»
- Ввод текстом: `Продукты 1500`, `Такси - 500`, `Кофе 150,50`
- Кнопка «Добавить трату»: сетка категорий, затем сумма и необязательное пояснение (`1500 пятерочка`). Пример пояснения подбирается под выбранную категорию
- После записи бот показывает, сколько всего потрачено за сегодня
- Статистика в том же сообщении: за сегодня, за месяц, за всё время, по месяцам, по категориям и кто сколько потратил (с долей в процентах)
- Удаление одной из 6 своих последних записей с подтверждением. Чужие записи удалить нельзя
- История хранится целиком. Границы дня и месяца считаются в часовом поясе `TIMEZONE` (по умолчанию `Europe/Moscow`)
- Общий бюджет: все whitelist-пользователи пишут в одну базу

## Стек

- Node.js + TypeScript
- Telegraf
- PostgreSQL + Prisma

## Быстрый старт

### 1. Зависимости

```bash
npm install
```

### 2. PostgreSQL

Нужен запущенный Docker Desktop, затем:

```bash
npm run db:up
```

Это поднимет только Postgres на порту `5433` (логин/пароль/БД: `budget` / `budget` / `budget_wallet`). Порт `5433` выбран, чтобы не конфликтовать с локальным Postgres на `5432`. Сам бот в контейнер не попадает.

### 3. Переменные окружения

```bash
cp .env.example .env
```

Заполните `.env`:

| Переменная             | Описание                                                  |
| ---------------------- | --------------------------------------------------------- |
| `BOT_TOKEN`            | Токен от [@BotFather](https://t.me/BotFather)             |
| `DATABASE_URL`         | Строка подключения (для Docker из примера уже подходит)   |
| `ALLOWED_TELEGRAM_IDS` | Telegram ID через запятую, например `111111111,222222222` |
| `TIMEZONE`             | Часовой пояс дня и месяца, по умолчанию `Europe/Moscow`   |

Узнать свой ID можно у [@userinfobot](https://t.me/userinfobot).

### 4. Миграции и Prisma Client

```bash
npx prisma migrate deploy
npx prisma generate
```

Для разработки с созданием новых миграций:

```bash
npm run db:migrate
```

### 5. Запуск бота

```bash
npm run dev
```

В Telegram откройте бота и отправьте `/start`.

## Команды

- `/start` — приветствие и главное меню
- `/menu` — главное меню

Главный экран: «Статистика», «Добавить трату», «Удалить запись». Кнопки меняют текущее сообщение. «Назад» возвращает на предыдущий экран. На отчёте других кнопок нет.

## Стартовый экран

До нажатия Start Telegram показывает блок «Что умеет этот бот?»: баннер и текст под ним. Этот текст виден только в пустом чате. Если переписка уже есть, удалите чат с ботом и откройте его снова, не нажимая Start.

Описание и короткая строка About бот выставляет сам при запуске. Картинку баннера нужно загрузить один раз через [@BotFather](https://t.me/BotFather):

1. Отправьте `/mybots` и выберите бота.
2. Откройте Edit Bot → Edit Description Picture.
3. Отправьте `src/assets/images/poster.jpg` как фото, не как файл. Это JPEG 640×360.

Кнопка Start штатная, её вид изменить нельзя. Аватар бота лежит в `src/assets/images/avatar.png`, его загружают через Edit Bot → Edit Botpic.

## CI и деплой

Локально ничего не меняется: Postgres в Docker, бот через `npm run dev`.

Полный стек в контейнерах — тот же режим, что будет на сервере. Сначала остановите `npm run dev`: у бота один токен, два процесса одновременно конфликтуют в Telegram.

```bash
npm run app:up
```

Остановка: `npm run db:down`. Данные Postgres остаются в volume.

### CI

На каждый push и pull request workflow [CI](.github/workflows/ci.yml) выполняет `npm ci`, проверку форматирования, линтер, проверку типов (код и тесты), тесты Vitest, сборку TypeScript и сборку Docker-образа. Образ никуда не публикуется.

Те же проверки локально:

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

### Деплой

Сервера пока нет, поэтому [Deploy](.github/workflows/deploy.yml) запускается только вручную и сам ничего не выкатывает, пока не заданы секреты.

Когда появится сервер:

1. Установите Docker и Docker Compose.
2. Склонируйте репозиторий. `git pull` на сервере должен проходить без пароля.
3. Положите `.env` рядом с кодом (`BOT_TOKEN`, `ALLOWED_TELEGRAM_IDS`, `DATABASE_URL`, при необходимости `TIMEZONE`). В контейнере строка подключения подменяется на Postgres внутри Docker-сети.
4. В GitHub: Settings → Secrets and variables → Actions:

| Секрет           | Значение                       |
| ---------------- | ------------------------------ |
| `DEPLOY_HOST`    | IP или домен                   |
| `DEPLOY_USER`    | SSH-пользователь               |
| `DEPLOY_SSH_KEY` | Приватный ключ                 |
| `DEPLOY_PATH`    | Каталог репозитория на сервере |

5. Actions → Deploy → Run workflow.

Workflow заходит по SSH, делает `git pull` и `docker compose --profile deploy up -d --build`. При старте контейнер применяет миграции и запускает бота.

## Известные ограничения

- «По месяцам» загружает в память все записи за всю историю и группирует их в коде. Для семьи это тысячи строк, но при росте стоит перейти на SQL-группировку (`date_trunc('month', "createdAt" AT TIME ZONE ...)` через `$queryRaw`).
- В `Expense.category` хранится отображаемое название категории, а не `slug`. Переименование категории разделит старые и новые записи в статистике; понадобится миграция данных.
- `Expense.amount` — `Int` в копейках. Одна запись ограничена примерно 21,4 млн ₽; суммы в отчётах считаются агрегатами, и при очень большой истории стоит перейти на `BigInt`.
- Незавершённый ввод (выбрана категория, но сумма ещё не написана) хранится в памяти процесса 15 минут и теряется при перезапуске бота.
- `npm audit` показывает уязвимости в `deepmerge-ts` и `mysql2` (транзитивно через CLI `prisma`, бот их не использует) и в `tinypool` / `@vitest/mocker` (только для тестов). Исправление требует мажорных обновлений `prisma` и `vitest`.
